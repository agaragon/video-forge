# Job Processing

Source: [`Kickoff.md`](../Kickoff.md) §4.3. See [`README.md`](./README.md) for
the EARS legend. Checkbox = implemented in the current codebase.

- [x] **REQ-JOB-1** — When a user submits an encoding job, the system shall enqueue the job and return a unique job identifier. _Implemented: `internal/job.Manager.Submit` generates an ID (`job.NewID`), stores the job, and pushes it onto the queue; `POST /api/v1/jobs` returns the job snapshot including `id`._
- [x] **REQ-JOB-2** — While an encoding job is running, the system shall report progress as a percentage of completion. _Implemented: `media.Encoder.Encode` parses ffmpeg's `-progress pipe:1` stream into a percentage against the probed source duration; `GET /api/v1/jobs/{id}/events` streams it over SSE._
- [x] **REQ-JOB-3** — While an encoding job is running, the system shall allow the user to cancel that job. _Implemented: `Manager.Cancel` cancels the job's context, which `DELETE /api/v1/jobs/{id}` exposes for both running and still-pending jobs._
- [x] **REQ-JOB-4** — When a user cancels a running job, the system shall stop the encoding process and release its resources within a bounded time. _Implemented: cancelling the job's `context.Context` kills the ffmpeg child process (`exec.CommandContext`), and `Manager.runJob` removes the partial output file._
- [x] **REQ-JOB-5** — When an encoding job completes successfully, the system shall make the output file available for download. _Implemented: `Job.complete` transitions to `StateCompleted`; `GET /api/v1/jobs/{id}/download` streams the file once in that state._
- [ ] **REQ-JOB-6** — While the job queue is at maximum capacity, when a user submits a new job, the system shall place the job in a pending state and report its queue position. _Partially implemented: every submitted job is placed in `StatePending` with a reported `queue_position` (`internal/job.Job.queuePosition`), but the v1 in-memory queue is unbounded rather than capacity-bounded (see `VIDEOFORGE_QUEUE_CAPACITY`, currently unenforced) — jobs are never rejected for being "at capacity"._
- [x] **REQ-JOB-7** — If an encoding job fails, then the system shall record the failure reason and notify the user. _Implemented: `Manager.runJob` records the ffmpeg error via `Job.fail`; the reason is available on the job snapshot's `error` field (polling and SSE)._
- [x] **REQ-JOB-8** — If the encoding engine crashes during a job, then the system shall mark the job as failed and free the associated resources. _Implemented: any non-cancellation, non-timeout `ffmpeg` failure falls through to `StateFailed` in `Manager.runJob`, and the partial output is removed._
- [x] **REQ-JOB-9** — If an encoding job exceeds its configured maximum duration, then the system shall terminate the job and mark it as timed out. _Implemented: each job runs under `context.WithTimeout(parent, cfg.JobTimeout)`; a `context.DeadlineExceeded` result transitions the job to `StateTimedOut`._
